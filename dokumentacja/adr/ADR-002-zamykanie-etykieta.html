ADR-002 · PRZYJĘTA · 20.09.2026

Zamykanie dyskusji etykietą

Jedno nadanie etykiety kończy wątek bez decyzji regulaminowej i zleca odświeżenie strony.

Problem i wybór

Dyskusja #28 pozostawała na stronie wśród otwartych po zamknięciu na GitHubie, ponieważ publikacja przechowywała wcześniejszy stan. GitHub nie wymienia zdarzeń closed i reopened dla Discussions w dokumentacji wyzwalaczy Actions. Nie opieramy rozwiązania na tych zdarzeniach.

Wybrano obsługiwane zdarzenie nadania etykiety. Odrzucono częstszy harmonogram jako główne rozwiązanie: nie daje natychmiastowej reakcji i bywa opóźniany. Dotychczasowy harmonogram pozostaje zabezpieczeniem.

Przyjęty mechanizm

Nadana etykietaPowód zamknięciaWynik
PORZUCONAOUTDATEDZamknięcie bez rozstrzygnięcia komisji
DUPLIKATDUPLICATEZamknięcie powielonego wątku
Nadanie etykiety → odczyt aktualnego stanu → zamknięcie → jawne uruchomienie Release na main → karta w zwijanym archiwum.

Obsługa obejmuje dyskusje repozytorium. Publikacja na stronie nadal stosuje istniejący filtr kategorii. Karta znika z otwartych po zakończeniu Release, nie natychmiast po kliknięciu etykiety. Czas zależy od kolejki Actions i pamięci podręcznej Pages; brak gwarancji czasu. Przycisk odświeżania jedynie ponownie ładuje opublikowaną stronę.

Granice i bezpieczeństwo

  • Brak zmian Markdown, DOCX i kart DR; brak komentarzy publikowanych w imieniu użytkownika.
  • Workflow ma tylko contents: read, discussions: write i actions: write. Nie ma uprawnień zapisu kodu ani tworzenia PR-ów.
  • Sprawdzamy aktualne etykiety, nie tylko historyczny payload. Usunięta etykieta oznacza pominięcie.
  • Sprzeczne etykiety (obie zamykające lub etykieta decyzji) oraz inny istniejący powód zamknięcia zatrzymują automat.
  • Ponowienie dla już zamkniętej dyskusji z właściwym powodem tylko uruchamia publikację. Błąd API lub publikacji jest widoczny w Actions.
  • Usunięcie etykiety nie otwiera dyskusji. Przy ręcznym otwarciu należy usunąć etykietę zamykającą i odświeżyć publikację. Ręczne zamknięcie bez nadania etykiety nadal korzysta z harmonogramu albo ręcznego Release.
  • Brak automatycznego przetwarzania starych etykiet przy wdrożeniu. Aby uruchomić nowy mechanizm dla takiego wątku, usuń i nadaj etykietę ponownie.

Plan wdrożenia i odbiór

  1. Testy RED: oba powody zamknięcia, ponowienie, cofnięta etykieta, konflikty i błędy API.
  2. Skrypt wywołujący GitHub CLI i workflow uruchamiany przez labeled; bez nowych zależności.
  3. Pełne testy, CI i build strony; przegląd różnic potwierdza brak zmian regulaminu.
  4. Po scaleniu na main nowo nadane etykiety uruchamiają automat. Nie zmieniamy istniejących dyskusji wyłącznie w celu testowania.
