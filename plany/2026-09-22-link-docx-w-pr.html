DOCX do sprawdzenia w opisie PR

Stała sekcja na górze opisu PR. Aktualizowana przez skrypt, bez LLM i bez ponownego wdrażania decyzji.

Uzgodnione działanie

Po udanym wygenerowaniu i sprawdzeniu dokumentu automat dodaje sekcję „DOCX do sprawdzenia” z linkiem do DOCX przypiętym do pełnego SHA commita, linkiem do źródła Markdown i uruchomienia Actions. Zachowuje pozostały opis PR. Kolejne wykonanie aktualizuje tę samą sekcję, nie dopisuje duplikatu.

Alternatywa: komentarz bota. Odrzucona na rzecz widocznej sekcji opisu, zgodnie z wyborem Fencer4Life.

Zakres i bezpieczeństwo

Wspólny skrypt Python wykorzystuje GitHub CLI/API, bez nowych zależności. Włączenie po udanym wdrożeniu w istniejącym lub nowym PR, także w szybkiej ścieżce. Publikacja linku sprawdza aktualny SHA gałęzi PR; nie publikuje linku do innej wersji. Błąd publikacji zatrzymuje workflow z komunikatem; nie cofa poprawnego DOCX.

Osobne wywołanie samego publikatora pozwala naprawić opis PR #57 bez ponownego stosowania DR-025. Skrypt sprawdza obecność plików DOCX i Markdown w podanym commicie. Nie zmienia regulaminu, nie scala PR, nie zmienia etykiet ani modelu zatwierdzania.

TDD i sprawdzenie końcowe

  1. RED: testy dodania sekcji, aktualizacji bez duplikatów, zachowania opisu, kodowania URL i odrzucenia nieaktualnego SHA.
  2. GREEN: implementacja publikatora i podłączenie obu ścieżek workflow; pełny zestaw testów.
  3. Wykonanie tego samego skryptu na PR #57. Odczyt opisu z GitHuba i potwierdzenie docelowego SHA linku. Powtórzenie publikacji nie zmienia opisu.
  4. Osobny PR z kodem automatu, testami i instrukcją. Bez ręcznego dopisywania linku jako substytutu automatyzacji.

Zakres: wyłącznie widoczność wygenerowanego dokumentu w PR. Decyzja i treść regulaminu pozostają bez zmian.
